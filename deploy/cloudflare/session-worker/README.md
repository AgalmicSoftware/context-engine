# Context Engine Session Worker — Deploy to Cloudflare

This is the isolated, checksummed Cloudflare-native deployment package for a
single user-owned Context Engine Session Worker. Cloudflare provisions the
Worker, KV namespace, and Durable Object in the deployer's account. No Context
Engine deploy helper, Cloudflare API token, OAuth token, or preinstalled agent
is involved.

Use the immutable-commit Deploy to Cloudflare link supplied by Context Engine.
The link must name a 40-character public replay commit, not a moving branch.

During Cloudflare setup:

1. Choose unique Worker and KV names.
2. Set `DEFAULT_SESSION_SLUG` to the exact session slug from Context Engine.
3. Set `BOOTSTRAP_ADMIN_ADDRESS` to the public admin address shown after
   Context Engine passkey login. Never enter a private key or seed phrase.
4. Keep `CE_WORKER_GROUPS_BOOTSTRAP=fresh-template-v2` only when `GROUP_KV`
   is the newly provisioned namespace from this deployment. Existing Group
   data must complete the legacy reconciliation workflow before mutations.
5. Paste the two independent setup secrets generated by Context Engine into
   `TOKEN_HMAC_SECRET` and `CE_STORAGE_ENVELOPE_KEK`.
6. Deploy, then copy the resulting `https://<worker>.<account>.workers.dev/`
   URL back into the Session Wizard.
7. Let the wizard perform the signed initial configuration write, verify the
   Worker, and erase its in-memory copies of the two setup secrets.

The setup secrets are runtime secrets for the deployed Worker, not Cloudflare
credentials. Cloudflare stores them as encrypted Worker secrets. They are never
sent to a Context Engine-operated origin.

## Package integrity

`worker.mjs` is generated from `workers/sessionCorsWorker/worker.js` and all of
its required shared modules. `template-manifest.json` records every package
file's SHA-256 plus a canonical package SHA-256. The build fails closed when the
generated bundle and checked-in package diverge.

From the repository root:

```bash
npm run worker:cloudflare-template
npm run verify:cloudflare-template
```

The deployed Worker remains functional if `contextengine.sh`, its OAuth client,
or every Context Engine-operated dynamic service later disappears. The fork
created by Cloudflare remains in the user's Git provider account for recovery
and upgrades.

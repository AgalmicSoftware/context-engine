# Arweave Payload Examples (Surveys + SBTs)

This doc captures example JSON payloads that are uploaded to Arweave and the
matching object shapes that `contractScripts` expects when calling into the
contracts. These examples reflect the current JSON generation logic in:
- `client/src/components/SurveyTool/CreateQuestionsAndSurveys.tsx`
- `client/src/components/SurveyTool/SurveyTool.tsx`
- `client/src/components/SBTs/CreateSBTGroup.tsx`

It does not document session metadata JSON; that lives in
[`docs/session-registry.md`](session-registry.md).

All examples use `contextEngine` names.

## Runtime read caching (Arweave)

Arweave payload reads are now cache-first in the client:

- `arweaveClient.downloadDataFromArweave(txId)` uses (`arweaveClient` remains a compatibility alias):
  - in-memory text cache (TTL-based),
  - in-flight request dedupe per `txId`.
- `contractScripts` stores per-session payload text cache in `questionsCache` under:
  - `arweaveTxCache[txId] = { text, savedAtMs }`
- Display-critical metadata reads are gateway-first by default:
  - session metadata and SBT metadata skip the GraphQL tx-existence precheck unless a deployment explicitly re-enables it
  - question and survey metadata already use explicit no-precheck/gateway-first reads
  - response payload precheck remains configurable separately
- Concurrent reads for the same tx id are coalesced before hitting gateways.
- Doc library fallback blob reads no longer force `cache: 'no-store'`.

If needed, callers can bypass the in-memory Arweave text cache with:

- `downloadDataFromArweave(txId, { bypassCache: true })`

## Locked-field no-leak contract

When a field is locked, the uploaded Arweave JSON must store only a neutral public value plus the encrypted envelope. Writers must not keep a plaintext alias, display copy, raw tag list, raw document URL, or response value beside the encrypted envelope.

Canonical neutral public values are:
- strings: `""`, `"*"`, or `"[encrypted]"` depending on the existing reader contract
- arrays: `[]`
- ratings: `null` when `importanceEncrypted` or `convictionEncrypted` is present

The canonical envelope locations are:
- survey metadata: `titleEncrypted`, `documentURLsEncrypted`
- question metadata: `promptEncrypted`, `optionsEncrypted`, `tagsEncrypted`
- response payloads: `answer.encryptedPortion`, `additional.encryptedPortion`, `importanceEncrypted`, `convictionEncrypted`
- SBT tokenURI metadata: `encryptedFields.<field>`

New upload paths validate this contract before posting to Arweave.

## SBT tokenURI payload (Arweave JSON)

Generated by `CreateSBTGroup.uploadTokenUriToArweave` and stored on Arweave.
`contractScripts.createSBT(..., tokenURI, ...)` expects the Arweave tx id (not the full URL).

Notes:
- For asset-like fields (for example `image`, `logo`, `sessionHeaderImg`), the UI accepts any of:
  - Full gateway URL: `https://ar-io.dev/<txId>` (with `https://arweave.net/<txId>` still accepted)
  - Arweave URI: `ar://<txId>`
  - Bare txId: `<txId>` (43-char base64url)
  The client normalizes `ar://` and bare txIds to a gateway URL via `normalizeArweaveUrl` (`client/src/utilities/arweave/arweaveUrls.ts`).
- Debugging: if you see browser console errors like `Failed to load resource ... (<txId>, line 0)`, check the Network tab for the full URL:
  - If the request is to your app origin (for example `http://localhost:3000/<txId>`), some UI is rendering a bare txId as a relative URL.
    Normalize before rendering.
  - If the request is to an Arweave gateway (for example `https://ar-io.dev/<txId>` or `https://arweave.net/<txId>`), the content itself is missing (bad txId or still propagating).
    Verify the tx exists on the configured gateway or fix the underlying metadata pointer.
  - Runtime reads default to direct AR.IO-only routing (`https://ar-io.dev/<txId>`) and spend their retry budget there.
    Legacy multi-gateway fanout (`https://arweave.net`, Irys, Permagate, and alternate raw/tx-data routes) is available only when
    `REACT_APP_CE_ARWEAVE_DIRECT_TO_AR_IO=false` or `window.CE_ARWEAVE_DIRECT_TO_AR_IO = false` is set intentionally.
- `documentURLs` is the canonical source-reference field. Readers also tolerate
  legacy aliases such as `docURL`, `docURLs`, `documentUrl`, and
  `documents[].href`, then normalize them to `sbtInfo.documentURLs` before the
  SBT detail page's More section renders document links.

> **Removed field:** `adminRecovery.encryptedPassword` was previously included in group-password SBT metadata but has been removed. The field encrypted the group password using the creator's public address as the key, making it trivially recoverable by anyone who could read the tokenURI. New SBTs no longer include this field. Existing SBTs with this field in their metadata are not affected operationally (the field is ignored by the client), but the password may be recoverable from historical metadata.

Notes:
- Locked SBT names are not stored in plaintext in tokenURI metadata. When the name field is locked, the deployed public ERC-721 contract `name()` uses a generated placeholder such as `CE-SBT-12`.
- `CreateSBTGroup` intentionally exposes a single canonical session lock audience for SBT metadata fields. Even if SessionRegistry defines multiple per-resource gates (`ai`, `docUrls`, etc.), the SBT field-lock popovers collapse to the session's default gate instead of letting authors pick resource-specific gates per field.
- URL-mode image locks store the encrypted URL envelope at `encryptedFields.image`; upload-mode image locks store a minimal Lit-Arweave descriptor object (`storage` + `txId`) like the example above.
- The public tokenURI JSON no longer stores a synthetic `lit://arweave/...` URL, original upload filename, or MIME type for locked uploaded images. The client derives any Lit-Arweave pointer from `txId`, and the real file metadata stays inside the encrypted Arweave payload.
- Public/unlocked SBT metadata still uses the same top-level fields; `encryptedFields`, `encryptedFieldGates`, and `encryption` are omitted when no locks are selected.

## Question payload (Arweave JSON)

Generated by `CreateQuestionsAndSurveys.createSurvey` and uploaded to Arweave before
`contractScripts.addSurveyWithQuestions` or `contractScripts.addQuestions`.

```json
{
  "id": "0x2b6f...c0b1",
  "type": "multichoice",
  "prompt": "[encrypted]",
  "options": [],
  "singleSelect": false,
  "tags": [],
  "creator": "0xF39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
  "associatedSurveyId": "0x8d9e...f1c2",
  "sessionName": "contextEngine",
  "encryption": {
    "enabled": true,
    "status": "lit-v1",
    "gate": {
      "type": "sbt",
      "sbtAddresses": ["0xSBT_ADDRESS"],
      "chainId": 31337,
      "litChain": "ethereum",
      "mode": "any"
    },
    "targets": {
      "survey": true,
      "questions": true,
      "questionTags": true,

  },
  "promptEncrypted": {
    "v": 1,

      "surveyId": "0x8d9e...f1c2",
      "qId": "0x2b6f...c0b1:prompt"
    }
  },
  "optionsEncrypted": {
    "v": 1,
    "cipher": "xchacha20-poly1305",
    "ciphertext": "base64...",
    "nonce": "base64...",
    "aad": {
      "contextHex": "0x...",
      "chainId": 31337,
      "surveyId": "0x8d9e...f1c2",
      "qId": "0x2b6f...c0b1:options"
    }
  },
  "tagsEncrypted": {
    "v": 1,
    "cipher": "xchacha20-poly1305",
    "ciphertext": "base64...",
    "nonce": "base64...",
    "aad": {
      "contextHex": "0x...",
      "chainId": 31337,
      "surveyId": "0x8d9e...f1c2",
      "qId": "0x2b6f...c0b1:tags"
    }
  }
}
```

Notes:
- For multichoice questions, set `singleSelect: true` to enforce a single option; omit or set `false` for multi-select.
- Question tag encryption is controlled by `encryption.targets.questionTags` and defaults to enabled when prompt encryption is enabled in CreateQuestionsAndSurveys.
- `encryption.gate` can mirror the first entry in `encryption.gates`; this compatibility alias is expected for mixed old/new readers.
- Survey/question/response payloads use `sessionName` as the canonical session identity key; legacy `groupName` is still normalized on reads.
- Off-chain/client/agent records should carry `storageRef` as the backend-agnostic payload pointer and preserve `arweaveTxId` for Arweave compatibility. Readers prefer `storageRef` and fall back to `arweaveTxId`. Cloudflare-backed records use opaque worker refs and do not synthesize Arweave ids.
- New survey/question writes keep `groupName` as a blank reserved field (`""`) so it no longer duplicates `sessionName`; this reserved field can be repurposed later for SBT association metadata.
- Response payloads may include `surveyTitle` and `prompt` for public metadata, but locked survey titles and locked question prompts are copied as `"[encrypted]"` so decrypted UI state is not re-uploaded.
- Question payloads are cached client-side in the managed `questionsCache` namespace (logical key `dg:questionsCache:<slug>`) via `cacheScripts` (IndexedDB primary, localStorage fallback), and fields such as `singleSelect` are preserved for consistent rendering.

SBT tokenURI metadata session-linking:
- Canonical link field is `sessionSlug`.
- Legacy `slug`/`groupSlug` and `sessionName`/`groupName` may still be read for backward compatibility, but new SBT writes should include `sessionSlug`.

## contractScripts import formats

These are the canonical object shapes expected by `contractScripts` calls.

```js
import contractScripts from 'client/src/utilities/web3/contractScripts.js';

// Survey + questions (survey + question payloads are the JSON above)
await contractScripts.addSurveyWithQuestions(
  'wagmi',
  surveyId,          // string or bytes32
  surveyData,        // Survey payload (Arweave JSON)
  questionIds,       // array of ids (string or bytes32)
  questionDataArray, // array of Question payloads (Arweave JSON)
  groupCfg
);

// Standalone questions
await contractScripts.addQuestions(
  'wagmi',
  questionIds,
  questionDataArray,
  surveyIds,         // bytes32(0) for standalone questions
  groupCfg
);

// Responses (surveyResponse + per-question response payloads above)
await contractScripts.submitResponses(
  'wagmi',
  questionIds,
  questionResponses, // array of response objects
  surveyId,
  surveyResponse,
  groupCfg
);

// SBT create (tokenURI is the Arweave tx id)
await contractScripts.createSBT(
  'wagmi',
  sbtName,
  sbtSymbol,
  limitedNumber,
  adminAddress,
  mintingEndTime,
  hasPasswordMint,
  burnAuth,
  hashedPasswords,
  tokenUriTxId,
  groupPasswordHash,
  groupCfg
);
```
